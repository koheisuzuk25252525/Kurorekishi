# 黒歴史ノート・クロニクル

自分の設定を本物の力にしていく、縦持ちiOSゲームの試作。
スキル獲得は購入ではなく、新しい危機に設定で応え、その力で戦って証明する体験にする。

## Macで起動・更新

Xcode 15以降、iOS 17以降のiPhoneシミュレータを使用。XcodeGenは不要。

```sh
git clone -b main https://github.com/koheisuzuk25252525/Kurorekishi.git
cd Kurorekishi
open iOS/Chronicle.xcodeproj
```

ChronicleスキームとiPhoneシミュレータを選び、Cmd+Rで実行。
既存のフォルダを更新するときは、同フォルダのターミナルで実行する。

```sh
bash scripts/sync-mac.sh
git log -1 --oneline
```

更新後はXcodeで実行中のアプリを停止し、Cmd+Rで再ビルド・起動する。
更新したフォルダとXcodeで開いているフォルダが同じであることを確認する。

## 今回の体験

- 通常攻撃が効かず、敵が迫る。ノートに書いた封印を解くと、漆黒拳が現実になる。
- 最初の能力に寄った画面が引き、未習得の枝が広がる。習得1/10と最初の一点を明示。
- 系譜は漆黒拳を起点に、右腕・魔眼・詠唱の3方向へ広がる。
- 9つの獲得エピソードには、それぞれ場所、敵、現在の力の限界、新しい設定、詠唱、結末を用意。
- エピソード開始 → 今の力が通用しない → 次の設定を刻む → 覚醒した能力で戦闘 → 勝利で習得。
- 獲得後は系譜の新しいノードが光り、複合能力が成立すると共鳴を表示する。
- 敗北時は新能力を獲得せず、元の設定へ戻して再挑戦。途中終了後は保存した場面から再開する。

系譜に表示する10能力：

| 共通の起点 | 右腕 | 魔眼 | 詠唱 |
| --- | --- | --- | --- |
| 漆黒拳・第一拘束解除 | 黒龍顕現 | 魔眼開放 | 長文詠唱 |
| | 神喰らいの右腕 | 因果を視る眼 | 終焉ノ詠唱 |
| | 終焉を掴む手 | 世界の理を視る眼 | 真名解放 |

JSONには基礎設定3つも含めて13ノードを収録。基礎設定は対応エピソードで一緒に取得する。
全10能力は今回のプレイ可能な範囲であり、将来の全編の規模を示すものではない。

## 保存・試遊

ゲーム進行は既存の保存キーを維持。今回の導入フラグだけをv4に更新しているので、
既存セーブがあっても新しい系譜の獲得演出を一度確認できる。旧進行は失わない。
新規体験を通して確認する場合は「書き直す」で初期化する（確認ダイアログあり）。

1. 初回導入後、系譜に「習得1/10」と最初の一点が表示されることを確認する。
2. 「封印の奥で、何かが嗤う」を選び、黒龍の覚醒から勝利、習得まで進める。
3. 次の能力「神喰らいの右腕」のエピソードが出現することを確認する。
4. 魔眼のエピソードを進め、右腕との共鳴を確認する。
5. エピソード途中で終了し、再起動して同じ場面から再開することを確認する。

## 自動同期

Macで一度だけ実行すると、ログイン中は60秒ごとにGitHubのmainを取得する。

```sh
bash scripts/install-mac-sync.sh
```

更新経路は「Codexで変更を検証・コミット・mainへpush → Macが取得 → Xcodeで再実行」。
クラウドだけの未コミット変更は配信されない。実行中のアプリは自動更新されない。
Mac側で編集する場合は先に同期を停止し、保存してから扱う。
未追跡ファイルやローカル変更、main以外のブランチ、履歴の分岐があると安全のため取得を止める。
Xcodeの生成workspaceとユーザー設定はGitの管理対象外。

```sh
cat .mac-sync/sync.log
cat .mac-sync/sync-error.log
bash scripts/uninstall-mac-sync.sh
```

privateリポジトリではMac側のGit認証が必要。認証情報をスクリプトに埋め込まない。

## 構成と検証

- `Sources/ChronicleCore`：モデル、JSON、戦闘、獲得エピソードの進行。
- `iOS/ChronicleApp.swift`：導入、系譜、兆候の選択、エピソード、戦闘、保存。
- `Tests/ChronicleCoreTests`：進行、戦闘、各系統、報酬、敗北、保存互換性。

XcodeアプリはコアのSwiftファイルを直接コンパイルし、JSONをリソースへコピーする。
Swift Packageはロジックテスト用。アプリではBundle.main、テストではBundle.moduleを使用。

```sh
swift test
xcodebuild -project iOS/Chronicle.xcodeproj -scheme Chronicle \
  -sdk iphonesimulator -configuration Debug \
  -derivedDataPath DerivedData CODE_SIGNING_ALLOWED=NO build
```

従来の基礎機能に加え、代表3事件の戦術・敗北・保存互換性をXCTestで検証する。
SwiftUIファイルは構文チェック済み。iOSのビルド、画面のレイアウトと演出はMacでの確認が必要。
GitHub ActionsにもSwiftテストとiOSシミュレータ用ビルドを登録している。

全9事件で、黒龍の防御破壊・魔眼の見切り・妨害される詠唱と上位技の専用効果を実装。完成素材・音声は今後の拡張。
導入の危機とエピソードの最初の攻撃失敗は固定演出。その後の覚醒戦は実際の戦闘計算を使う。
費用による解放APIは既存テスト用に残しているが、通常の画面ではエピソードの勝利で習得する。

各クラウドタスクは既に隔離されているため、既存チェックアウトを使い、追加のworktreeは作らない。

## 戦闘改善・第1PR

[現状診断、戦闘の具体例、検証と後続ロードマップ](docs/GAMEPLAY_REVIEW.md)。
主操作は4つ。系統の専用行動・攻撃（詠唱中は解放）・防御・集中を使い、敵が次に行う予兆を読む。
黒龍は殻が硬直したときに壊す。魔眼は不可視の敵を捉え、飛びかかりを見切る。
詠唱は防御で妨害に備えてから重ね、強打前に解き放つ。
保存キーと導入v4は維持し、旧セーブ中の戦闘に新しい防御特性を後付けしない。
mainへの自動同期では未マージのPRは配信されない。試遊ブランチへの切替手順は上記資料を参照。
